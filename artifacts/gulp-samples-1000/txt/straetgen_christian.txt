10/2019 - 11/2019: Evaluierung Serverless auf AWS
 
 
Aufgaben:
 
Evaluierung Serverless auf AWS (API-Gateway, Network-Load-Balancer, Fargate-
Cluster, Docker)
    * Serverless Computing ermöglicht die Fokussierung auf die Applikation-
      Logik und eliminiert den Betriebsaufwand von physischen oder virtuellen
      Servern. In einem Trial setze ich eine Serverless-Applikation mit Docker
      und AWS Fargate um.
    * Das Projekt soll als Blaupause für spätere Services und Anwendungen
      dienen.
    * Es besteht aus zwei Service-Typen. Der erste, synchrone Typ wird über
      http(s) aufgerufen, der zweite läuft „headless“ und lauscht auf einer
      Queue (SQS). Beide sind als Docker-Container als Python-Prozess
      implementiert.
 
Build
Der Build der Docker-Container erfolgt über AWS CodeBuild. Die erstellten
Container-Images werden in die AWS Elastic Container Registry übertragen.
 
Dockerfile
    * Beide Service-Typen nutzen ein gemeinsames Docker-Basis-Image.
    * Basis-Image nutzt (FROM) ubuntu:18.04
    * Installiert weitere Pakete (RUN) mittels apt-get und conda.
    * Die jeweiligen konkreten Service-Images nutzen das Basis Image (FROM) und
      installieren die Anwendung in das Image (WORKDIR, COPY)
    * Die Anwendung wird dann mit ENTRYPOINT gestartet.
 
Relevante Architekturkomponenten und ihre Funktion
    * API-Gateway:
          o Nimmt http(s)-Request entgegen, validiert den API-Key und leitet
            den Request an den Network-Load-Balancer weiter. Im Fall des
            „headless“ Service, wird der Request in eine Queue (SQS)
            geschrieben
    * Network-Load-Balancer:
          o Verteilt Requests über verfügbare Container-Instanzen. Überwacht
            dabei den Health-Status dieser Container-Instanzen (in AWS
            Terminologie „Targets“ genannt)
    * Fargate Cluster:
          o Stellt sicher, dass Services gemäß Anforderung bereitstehen.
            Startet und Container-Instanzen und überwacht diese. Greift dabei
            auf die s.g. Task-Definition zurück.
    * Task-Definition:
          o Definiert Laufzeit-Parameter wie Speichermenge und CPU Einheiten.
            Docker Container Name, Image-Name, Port-Mappings und Environment-
            Variablen. Legt zudem fest mit welchen Berechtigungen (Execution-
            Role) der Container laufen soll.
 
Kenntnisse:
 
Docker, AWS Services: API-Gateway, Network-Load-Balancer, Fargate, CodeBuild
CodeCommit, git, Elastic Container Registry, Route 53)

    * Erstellung von 3 Komponenten zur Integration eines Payment Providers mit
      Sitz in Deutschland
    * Ein File-Prozessor (1. Komponente) fragt zyklisch ein konfiguriertes
      Verzeichnis auf neue Input-Files (SAP-IDOC) ab. Neue Files werden mit

      eine JMS-Message in eine entsprechende Queue geschrieben.

      transformiert in das Format des Zielsystems, führt einen REST-Call aus,
      und speichert das Ergebnis des REST-Calls in der Datenbank und erzeugt
      eine neue JMS-Nachricht. Die 3. Komponente konsumiert die Nachricht dann
