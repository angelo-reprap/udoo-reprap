01/2013 – 03/2013 ASP.NET Control für dynamische Formulare und Workflows
 
Branche: Solar-energy portal
Technologien: C#, ASP.NET, JavaScript, Knockout, jQuery-UI, XML, XSLT 1.0,
Webservices
Tools: Visual Studio 2010 und 2012, Redmine, SVN, ReviewBoard, Jenkins
Rollen: Systemarchitekt, Projektleiter (Team: 5)

Das Control verwendet eine XML-Spezifikationssprache um Workflows zu
definieren. Workflows bestehen aus Aktivitäten, die jeweils eine
Formularspezifikation und Übergänge zu anderen Aktivitäten enthalten.
 
Ein Formular besteht au seiner oder mehreren Seiten, die jeweils Felder
enthalten. Die Anwendung unterstützt die üblichen Feld- und Control-Typen wie
Boolean, Einfach- oder Mehrfachauswahlen, Text, Numerische werte usw. Die
Darstellung von Feldern, Seiten und Formularen kann mit generischen
(erweiterbaren) Optionen gesteuert werden, Felder unterstützen Typ-abhängig
verschiedene Validierungsmethoden.
 
Der Ablauf von Workflows wird von einem Webservice gesteuert und client-seitig
mit dynamischen HTML-Formularen implementiert, die Knockout (MVVM) und jQuery-
UI-Komponenten verwenden.
 
Das Layout und Design von Formularen ist sehr flexibel und verwendet modulare
XSLT-1.0 Renderer, die HTML-Fragmente und JS-Code generieren um das User-
Interface zu erzeugen.
 
Formular-Spezifikationen definieren eine XML-Sprache (oder ein JSON Format),
die die eingegebenen Daten repräsentiert. Webservices konsumieren diese Daten
(oder stellen sie der UI zur Verfügung). Die Implementierung des Services kann
ausgetauscht werden, alternative Implementierungen können per Konfiguration des
ASP.NET-Controls ausgewählt werden.

06/2012 – dato: XODL – Modellierung und Code-Generierung
 
Technologien: XSLT 2.0 (Saxon), Java, Maven, SQL, JCR (Jackrabbit), XML, XSD,
JAXB, JAXWS
Tools: Eclipse, Oxygen, Maven, Redmine, SVN, ReviewBoard, Jenkins
Rollen: Systemarchitekt, Product Owner, Projektleiter (Team: 6), Entwickler
 
Basis des Projekts ist eine XML-Modellierungs-Sprache, ähnlich zu UML/XMI
(allerdings auf einem etwas abstrakteren Niveau). Neben der Modelldefinition
unterstützt XODL die Definition von Code-Generierungs-Spezifikationen für
Zielplattformen.
 
Ein Code-Generierungs-Framework das auf modularen XSLT-2.0 Transformationen
aufbaut verwendet XODL um Code für Zielplattformen wie UML, ER-Modelle, SQL-
Skripte für Datenbank-Schema-Generierung, Objektmodelle (POJO/POCO-Klassen),
XML Schema und Serialisierungs- und Data-Access-Layer zu generieren.
 
Das XODL-Repository (derzeit basierend auf Jackrabbit) speichert und verwaltet
Modelle und Generatoren und kontrolliert die Versionierung von Sourcen (Modelle
und Generatoren) sowie von Auslieferungsdateien und Schnittstellen.
 
Der aktuelle Milestone des Projekts umfasst eine Version von XODL die sich
selbst spezifiziert (generiertes XML Schema), Java-Objektmodelle mit XML
Serialisierung unterstützt sowie teilweise die Generierung von DB-Schema und
Data-Access-Layern. Eine XML Sprache die Java-Source-Code partiell
repräsentiert sowie Sprachen für Code-Dokumentation wurden auch in XODL
spezifiziert.
 
Nächste Milestones sollen die Generierung von .NET-Code, bessere Datenbank-
Unterstützung, und verschiedene UI-Frameworks unterstützen.
 
XODL geht aus den Erfahrungen mit dem weiter unten beschriebenen Business-
Applikation-Framework und ähnlichen Projekten hervor.
 
09/2011 – 05/2012  Framework für Geschäftsanwendungen (Prototyp)
 
Technologien: C#,.NET Framework 4.0, Silverlight, MS-SQL-Server, PostgreSQL,
   XML, XSLT, WCF, Silverlight, WPF
Tools: Visual Studio 2010, Redmine, SVN, ReviewBoard, Jenkins
Rollen: Systemarchitekt, Projektleiter (Team: 4), Entwickler
 
Das Framework zielt darauf ab, einen möglichst großen Anteil an
Entwicklungsarbeiten für typische Dateneingabe, Reporting und
Trackinganwendungen durch formale Spezifikationen zu ersetzen.
 
Die Spezifikationssprache erlaubt es, um Graphenfunktionalität erweiterte ER-
Modelle zu definieren. Entitäten und Domänen-Typen werden dabei als abstrakte
Datentypen spezifiziert.
 
Die Core-API erlaubt es Modell-Definitionen aus bestehenden Datenbank- und XML-
Schema abzuleiten und bietet Roundtrip-Funktionalitäten (ein Abfallprodukt ist
die Möglichkeit DB-Schema und Inhalte zwischen unterstützten Datenquellen
automatisch zu migrieren).
 
Das Laufzeit-System besteht aus einem Silverlight-Client und einem WCF-Service,
der eine die Modellspezifikation (Meta-Daten) sowie Search-Funktionalitäten zur
Verfügung stellt. Datenänderungen werden mit Hilfe einer Transaktions-Sprache
durchgeführt (s.U.).
 
Die Core API steht sowohl in .NET als auch (eingeschränkt) in Silverlight zur
Verfügung (gemeinsame Code-Basis). Client-seitig werden Entitäten in
generischen Modell-Klassen (Dictionary, Dynamic POCOs) gehalten.
 
Änderungen an Modell-Klassen können mit einem Transaction-Recorder
aufgezeichnet werden. Der Recorder stellt sicher, dass nur valide Änderungen
durchgeführt werden können. Der Recorder kann auch die Reihenfolge von Aktionen
ändern oder Aktionen parallelisieren.
 
Das Ergebnis einer Recording-Session ist ein Transaktionslog, das auf die
Datenquelle (Datenbank, XML-Datei oder auch andere Sessions) angewendet werden
kann. Der Recorder kann sich unmittelbar bei jeder Änderung mit dem Server
synchronisieren, so dass der Server über client-seitige Änderungen informiert
ist und z.B. eine Konfliktvermeidungsstrategie implementieren kann. Es werden
nur Änderungen an den Server übermittelt, was das Datenvolumen erheblich
reduzieren kann.
 
Transaction-Logs können auch für hochwertige Audit-Trail-Funktionalitäten
verwendet werden.
 
Das Projekt wurde zugunsten einer Neuentwicklung im Prototyp-Stadium beendet,
da eine auf Code-Generierung basierende Lösung flexibler ist und die
generierten Komponenten sich besser in bestehende Softwareumgebungen
integrieren lässt.

Technologien: Ubuntu Server, Windows Server 2008, Virtualbox,

Rollen: Spezifikation des Prozesses, Integration der Komponenten,
   kleinere Entwicklungsarbeiten um die Tools besser zu integrieren.
 
Dieses Projekt umfasst die Spezifikation eines agilen Entwicklungsprozesses
(Scrum mit Exoskelett) sowie den Aufbau einer IT-Infrastruktur die den Prozess
so gut wie möglich unterstützt. Das Haupt-Ziel war es den Entwicklungsprozess
transparent zu gestalten und gleichzeitig die Entwicklungsteams so wenig wie
möglich mit unnötiger Bürokratie zu belasten.
 
Wir haben als Basis der Infrastruktur Redmine ausgewählt, da es eine effiziente
Oberfläche hat, alle benötigten Kommunikations- und Dokumentationswerkzeuge
bietet und sich gut mit anderen Tools integrieren lässt. Das Backlogs plugin
stellt eine sehr effiziente Unterstützung für Scrum zur Verfügung.
 
Als Versionsverwaltung verwenden wir SVN, vor allem wegen der guten
Unterstützung in IDEs und für zentrale Repositories.
 
Qualität, sowohl als messbare Größe als auch als Ziel war eine Haupt-
Priorität. 
 
Den im Prozess vorgesehenen Peer-Reviewprozess haben wir mit ReviewBoard
implementiert das automatisch per Email Review-Requests versendet wann immer
Versionen eingecheckt werden.
 
Für die Implementierung von Continuous-Integration-Diensten haben wir uns für
Jenkins entschieden. Jede Source-Code-Version löst einen Build-, Deployment-
und Testrun aus. Ergebnisse der Builds und Tests werden mit Tickets und
Versionen verlinkt und in Redmine dargestellt.
 
Zusätzlich haben wir BBB (Blue Button) als Web-Conferencing und Demo-Plattform
und Zimbra für Email und Kalenderdienste zur Verfügung gestellt.
 
Jeder Service wurde in einer separaten VirtualBox VM deployed, die auf zwei
Servern redundant betrieben werden.

11/2007 – 12/2011 Sample Tracking, Clinical Information Management
 
Branche: Health Care
Technologien: C#, .NET Framework 2-4, MS-SQL-Server 2005-2008, ASP.NET, XSLT,
WCF,
   Silverlight 2-4
Rollen: Systemarchitekt, Entwickler (große Teile des Backends, Suche, Custom
Code)
 
„Sample Tracking“ verwaltet den Lebenszyklus von Proben, Material und anderen
Entitäten die im Zusammenhang mit der Durchführung von klinischen Studien
dokumentiert werden, was im wesentlichen bedeutet den Zustand und die
Verarbeitungshistorie aller getrackten Objekte zuverlässig zu erfassen.
 
Eine besondere Herausforderung an die Entwicklung der Anwendung sind sehr
heterogene und konfliktierende Anforderungen, die sich daraus ergeben, dass
Business Areas und Country Organisationen des Kunden unterschiedliche Prozesse
verwenden und andere Daten (oder Formate) aufzeichnen, aber die gleiche
Anwendung mit der gleichen Datenbasis verwenden werden sollten. Da gleichzeitig
keine Ausfallzeiten in Kauf genommen werden können muss die  Anwendung im
laufenden Betrieb erweiter- und änderbar sein und ein sehr flexibles
Datenhaltungskonzept verwenden.
 
Die Anwendung verwendet eine 3-tier Architektur. Die erste Version verwendete
ASP.NET, C# und MS-SQL-Server 2005 und den XML Datentyp zur Speicherung von
Entitäten. Aufgrund von Skalierungsproblemen wurde das UI auf Silverlight und
das Datenmodel auf eine gekippte Struktur umgestellt.
 
Der Großteil der Anwendungslogik (Aktionen, Wizards, Validierung, etc.) wird in
Form von dynamisch ladbarem C#-Code implementiert, der von der Anwendung selbst
verwaltet wird.
 
Die Anwendung stellt eine sehr flexible und mächtige Suche zur Verfügung, die
Ausdrücke per UI erstellt und diese dann in hochoptimierte SQL-Abfragen
übersetzt.
 
Die Anwendung wurde mit dem Microsoft Suisse Innovation Award ausgezeichnet.
