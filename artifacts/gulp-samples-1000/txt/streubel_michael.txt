    * Architektur, Entwicklung, Qualitätssicherung Dieses System dient als
      Baustein für ein Instant Payment Notification-System.
    * Dies bedeutet: In einem Shop-System wird ein Bezahlservice eingerichtet,
      der sich des internationalen Online-Zahlungsservice PayPal (einer eBay-
      Tochter) bedient. Bei PayPal werden (Benutzer- und) Zahlungskonten
      unterhalten und man kann Geld elektronisch transferieren, auch per eMail.
    * Diese Zahlungskonten sind keine Bankkonten, sondern werden durch
      Bankkonten des Benutzers unterstützt.

      d.h. es sendet HTTP-messages mit umfangreichen StatusInformationen über
      eine Geldtransaktion.
    * Es wurde nun ein J2EE-System entwickelt, das diese Messages empfängt,
      auswertet und die gesamte Bezahlungstransaktion des Shop-Systems durch
      Transaktionen auf der Datenbank des Shop-Systems komplettiert.
    * Das bedeutet, wenn der Käufer des Shop-Systems seine Bezahlung über
      PayPal ausführt, so muß das Shop-System wissen, ob das PayPal-System den
      Zahlvorgang als erfolgreich oder als gescheitert aus welchen Gründen
      ansieht.
    * Erst wenn die PayPal-Transaktion ausgeführt ist, ist die gesamte Shop-
      Transaktion komplett.

J2EE; EJB (Entity und Session), XDoclet, JBoss, JBoss-IDE (JBoss-Eclipse-Plugin

Projekt Nr. 20
 
Laufzeit:                                 04/1998 - 12/2001
 
Kunde:                                    ClaimsNet Informationssysteme AG,
Motorcare Services GmbH
 
Projektname:                              ClaimsNet (KFZ-Schadenmeldungssystem)
 
Branche:                                  Versicherungen
 
Projektbeschreibung/Tätigkeit:
Architekt, Entwickler, Qualitätssicherung, Beratung In dem System kommunizieren
am KFZ-Schadenmeldungswesen beteiligte Partner (Versicherungen, Werkstätten,
KFZ-Gutachter, Abschleppunternehmen) in einem Web-basierten Intranet zur
Bearbeitung von KFZ-Schadenmeldungen. Es handelt sich um ein rein server-
gestütztes System, das in einem VPN für viele tausend Benutzer läuft. Das
System transportiert formular-gestützte Informationen. Die Applikationslogik
ist ausschließlich in Java geschrieben.
 
Das System wurde großenteils von mir selbst implementiert. Die wichtigsten zum
Einsatz kommenden Java-Mechanismen sind: Servlets (Server-Extensions in Java),
Java-Mail, JAF (Java Activation Framework), Java Beans, JNDI (Java Naming and
Directory Interface), JDBC (Java Database Connection), JFC (Java Foundation
Classes) für in die Browserseiten eingebettete Applets sowie natürlich die
Java-Klassen im Standardpaket. Das System läuft auf Netscape-Servern
(Enterprise, Directory, Messaging) und WebSphere-Application-Server und mit MQ-
Series. Die Kommunikation mit den Versicherungen erfolgt über ein MQ-Series-
basiertes Schnittstellensystem, das bestehende Anwendungen mit dem MQSeries-
basierten Transportsystem des GDV (Gesamtverband der deutschen
Versicherungswirtschaft) verbindet, der auf dieser Basis das sog. GDV-
Schadennetz betreibt. Letzteres operiert auf der Basis eines durch den GDV
definierten Modells von Geschäftsvorfällen im Schadenwesen (Schadenmeldung,
Kostenübernahme, Kalkulation/Rechnung, Sachverständigenbeauftragung und
bericht u. a.). Das System wurde später von mir zu einem Worflow-System
erweitert.
 
Persönlich eingesetzte Technologien:
Servlets, Java-Mail, JAF (Java Activation Framework), Java Beans, JNDI (Java
Naming and Directory Interface), JDBC (Java Database  Connection), Swing für in
die Browserseiten eingebettete Applets.

Branche:                                  Chemie/Pharma
 
Projektbeschreibung/Tätigkeit:
Architekt, Entwickler, Qualitätsssicherung EJB-basierter Dokumenten-Retrieval-
Server auf Basis von WebSphere Application-Server und DB2. Der Server bekommt
Anfragen von Unternehmensportalen zur Bereitstellung und Übermittlung von
Dokumenten (Sicherheitsdatenblätter), die in Datenbank und Filesystem
gespeichert sind. Er arbeitet nach dem MVC-Prinzip: Ein Servlet ist Controller,

Compound Document bezeichnet). Diese Form der Informationsübermittlung war ein
Vorläufer eines Web-Service auf der Basis von SOAP mit Attachments (diesen
Standard gab es zu der Zeit noch nicht).
 
Persönlich eingesetzte Technologien:
J2EE, WebSphere, DB2, Visual Age for Java, J2EE-Security, XML, UML
